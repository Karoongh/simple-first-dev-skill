# Home + Navigation Ideas (any product)

**Not a fixed default.** Propose structure, then wait for the product owner to approve labels, menu items, and Home content for this project.

## How to choose top-level navigation

1. List the top 3–5 jobs the main users do every day.
2. Group those jobs into the smallest number of clear destinations.
3. Give each destination a short, plain label.
4. Hide advanced or rare actions inside those destinations or behind role permissions.
5. Write down why each top-level item exists (decision log).

There is no universal magic number. A simple tool may need 4 items; a broader tool may need more. The test is: does every item earn its place for this project?

## Suggested structure (adapt freely)

Top-level examples (rename to fit the domain):

- Home / Workspace
- Main daily activity (orders, appointments, tasks, projects…)
- People or records (customers, patients, contacts, inventory…)
- Insights / Reports (if used often)
- Settings (usually admin-only or secondary)

## Home / primary workspace layout

Header:
- Product or workspace name
- Global search (if useful)
- User menu / role indicator

Primary action area:
- One or two large, obvious buttons for the most common tasks
- Easy to reach with a thumb on mobile

Widget / card area (personalizable):
- Status of today’s work
- Items that need attention
- Key numbers the user checks often
- Recent activity
- Shortcuts the user actually uses

Keep the default preset focused. Extra widgets can be turned on by the user.

## Role presets

Create a few presets that match real roles in the project (for example operator, manager, analyst).
Each preset is just a different set of visible widgets and sometimes different primary buttons.

## Rules when expanding

- New frequent action → try a primary button or a widget on Home first
- New occasional action → place it inside an existing destination or a modal/sheet
- New top-level item → only when the job is frequent, clearly distinct, and does not fit elsewhere; document the reason
